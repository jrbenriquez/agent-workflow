## v0.1.3 (2026-11-07)

- Use `agentic/` as the default branch prefix for new outcome groups. Existing
  repository conventions, explicit branch instructions and saved branches still apply.

## Previous changes

- Make supplied prototypes the visual baseline through decomposition, orchestration,
  implementation and verification. Require mapped, paired visual inspection and
  deviation records; functional checks cannot substitute for visual acceptance.
  Recheck affected screens after shared UI changes without resetting budgets.

- Add `plan-work` for discovery, approved previews, PRDs and agent reference
  packages; document its optional entry point and check independent installation.
- Preserve planning-package references and PRD/preview authority in outcome
  decomposition without adding runtime handoff or state dependencies.

- Make existing app stack choices authoritative over generic technology defaults
  during planning, implementation, verification and recalibration.

- Execute and resume outcome groups with dependency scheduling, separate group
  checkpoints, persistent branch identity, local defaults and integrated evidence.
- Preserve per-outcome schema version 1, handoff fields and attempt accounting.
- Bundle group policy with orchestrate-work and validate every installed reference.
- Add GitHub Actions checks for reference drift, generator regressions and local
  skill installs, with actionable failure messages and sync repair instructions.
- Validate skill YAML frontmatter, required name/description strings and unique
  names in CI, with file-specific repair messages.
